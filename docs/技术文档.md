## 1. 系统架构

### 1.1 模块划分

系统采用分层设计，自底向上分为物理层、控制层、学习层与接口层：

| 层 | 模块 | 职责 |
|----|------|------|
| 物理层 | `robotic_arm_new.py` | 运动学：正运动学、逆运动学、雅可比矩阵 |
| 物理层 | `robotic_arm_dynamics.py` | 动力学：质量矩阵、科氏力、重力；正/逆动力学；经典控制器 |
| 控制层 | `robotic_arm_optimization.py` | 优化控制：MPC、ILC |
| 学习层 | `robotic_arm_imitation.py` | 模仿学习：行为克隆（BC） |
| 学习层 | `robotic_arm_reinforcement.py` | 强化学习：PPO |
| 规划层 | `trajectory.py` | 关节空间与笛卡尔空间轨迹规划 |
| 表现层 | `visualizer.py` | 3D 可视化与动画 |
| 表现层 | `gui_control.py` | 交互式 GUI 控制面板 |
| 接口层 | `robotic_system.py` | 统一接口 `RobotSystem`，整合上述所有模块 |

### 1.2 继承关系

动力学类继承自运动学类，从而复用正运动学与雅可比：

```
RoboticArm  (运动学)
    └── RoboticArmDynamics  (动力学，扩展质量矩阵/动力学/控制)
```

这一继承关系意味着：任何 `RoboticArmDynamics` 实例同时具备完整的运动学能力（FK、IK、雅可比），控制器可以直接调用父类方法。

### 1.3 数据流

典型的"轨迹追踪"数据流：

```
用户目标(起止位姿)
    → TrajectoryPlanner 生成参考轨迹 {position, velocity, acceleration}
    → 控制器 (CTC/PID/MPC/ILC) 计算关节力矩 tau
    → RoboticArmDynamics.forward_dynamics 步进仿真
    → Visualizer 渲染
```

轨迹点统一采用字典结构 `{'time', 'position', 'velocity', 'acceleration'}`，其中笛卡尔轨迹规划只填充 `position`（关节角），速度/加速度由下游按需数值微分补出。这一约定使得不同规划方法产出的轨迹可被同一套控制器消费。

## 2. API 参考

以下列出核心类的主要方法。参数类型除特别说明外，关节量均为长度 6 的一维数组（`np.ndarray`）。

### 2.1 `RoboticArm`（运动学）

```python
arm = RoboticArm(num_joints=6)
```

| 方法 | 说明 | 返回 |
|------|------|------|
| `forward_kinematics(joint_angles=None)` | 正运动学，返回末端 4×4 齐次变换矩阵 | `np.ndarray (4,4)` |
| `get_end_effector_position()` | 末端位置 [x,y,z]（基于当前关节角） | `np.ndarray (3,)` |
| `set_joint_angles(angles)` | 设置关节角（内部裁剪到 ±π） | — |
| `jacobian(joint_angles=None, epsilon=1e-6)` | 位置雅可比（中心差分数值法） | `np.ndarray (3,6)` |
| `inverse_kinematics(target, initial_guess=None, method='jacobian', max_iterations=100, tolerance=1e-3)` | 逆运动学求解 | `(success: bool, angles: np.ndarray)` |

**示例**：

```python
arm = RoboticArm(num_joints=6)
arm.set_joint_angles([0.5, 0.5, -0.5, 0, 0.5, 0])
pos = arm.get_end_effector_position()          # -> [-0.6076 -0.5834 -0.141]

success, angles = arm.inverse_kinematics([0.3, 0.1, 0.4],
                                         initial_guess=np.zeros(6))
# success -> True
```

> **注意**：`inverse_kinematics` 求解失败时不修改机械臂内部状态（见 §4.1）。建议对困难目标点显式提供 `initial_guess`。

### 2.2 `RoboticArmDynamics`（动力学）

继承 `RoboticArm`，额外提供：

| 方法 | 说明 | 返回 |
|------|------|------|
| `mass_matrix(q)` | 质量矩阵 M(q) | `np.ndarray (6,6)` |
| `coriolis_matrix(q, q_dot)` | 科氏力矩阵 C(q,q̇) | `np.ndarray (6,6)` |
| `gravity_vector(q)` | 重力向量 G(q) | `np.ndarray (6,)` |
| `forward_dynamics(q, q_dot, tau)` | 正动力学：由力矩求加速度 | `np.ndarray (6,)` |
| `inverse_dynamics(q, q_dot, q_ddot)` | 逆动力学：由加速度求力矩 | `np.ndarray (6,)` |
| `simulate(q0, q_dot0, tau_func, t_span, dt, use_fixed_step)` | 仿真积分 | `(t, q_traj, q_dot_traj)` |

**自洽性示例**（逆动力学与正动力学互逆）：

```python
arm = RoboticArmDynamics(num_joints=6)
q = np.array([0, np.pi/4, -np.pi/4, 0, 0, 0]); qd = np.zeros(6)
tau = arm.inverse_dynamics(q, qd, np.zeros(6))   # 保持静止所需力矩
qdd = arm.forward_dynamics(q, qd, tau)           # -> [0,0,0,0,0,0]（精确抵消）
```

### 2.3 控制器

| 控制器 | 类 | `compute_control` 签名 |
|--------|-----|------------------------|
| PID | `PIDController` | `(q_desired, q_actual, q_dot_actual, q_dot_desired=None)` |
| 计算力矩 | `ComputedTorqueController` | `(q_desired, q_dot_desired, q_ddot_desired, q_actual, q_dot_actual)` |
| 笛卡尔阻抗 | `CartesianImpedanceController` | `(x_desired, q_actual, q_dot_actual)` |
| MPC | `MPCController` | `compute(q_current, q_dot_current, q_ref_trajectory)` |
| ILC | `ILCController` | `update(q_traj, q_dot_traj, q_ref, q_dot_ref=None)` |

### 2.4 `RobotSystem`（统一接口）

```python
system = RobotSystem(mode='dynamics')   # 或 'kinematics'
```

| 方法 | 说明 |
|------|------|
| `plan_trajectory(start, end, method='cubic', **kwargs)` | 规划关节轨迹 |
| `execute_trajectory(trajectory, controller_name='pid')` | 执行轨迹追踪（PID/CTC/MPC/BC） |
| `train_ilc_trajectory(trajectory, iterations=10, Kp_fb=20, Kd_fb=4)` | ILC 迭代学习 |

实例化时会打印已注册的控制器列表，便于确认各模块是否成功加载。

## 3. 核心算法说明

### 3.1 正运动学（DH 参数法）

采用标准 Denavit-Hartenberg 参数描述连杆间的坐标变换。每个关节的齐次变换矩阵由 `[θ_offset, d, a, α]` 四参数确定，末端位姿为各关节变换矩阵的连乘：

$$T_{end} = \prod_{i=1}^{6} T_i(\theta_i)$$

系统采用 UR5 的标准 DH 参数。核心连乘计算通过 Numba 的 `@njit` 编译为机器码，实测吞吐约 150,000 ops/sec。

### 3.2 逆运动学（阻尼最小二乘 DLS）

给定目标末端位置，逆运动学迭代求解关节角。在当前关节角附近，末端位置的微小变化近似为 `Δx ≈ J·Δθ`。据此反解关节角增量：

$$\Delta\theta = J^T (JJ^T + \lambda^2 I)^{-1} \cdot e$$

其中 `e = x_target - x_current` 为位置误差，`λ` 为阻尼系数。相比纯伪逆 `J⁺`，DLS 在奇异位形附近（`J` 接近降秩）仍能保持数值稳定，避免 `Δθ` 爆炸。

**设计要点**：
- 阻尼系数 `λ = 0.05`，在收敛速度与稳定性间折中。
- 单步增量做自适应限幅（`‖Δθ‖ ≤ 0.3`），防止远离目标时步长过大导致来回震荡。
- 对工作空间边界或奇异区附近的不可达点，求解会失败并返回 `success=False`——这是预期行为，非缺陷。

### 3.3 动力学（拉格朗日方法）

机械臂动力学遵循标准形式：

$$M(q)\ddot{q} + C(q,\dot{q})\dot{q} + G(q) + F\dot{q} = \tau$$

其中 M 为质量矩阵，C 为科氏/向心力矩阵，G 为重力向量，F 为关节摩擦。

- **质量矩阵** M(q)：通过各连杆的速度雅可比与角速度雅可比累加得到，并叠加电机转子惯量以保证正定、避免奇异。
- **科氏矩阵** C(q,q̇)：通过 Christoffel 符号计算，其中 `∂M/∂q` 采用数值微分。此部分为两层数值微分嵌套（`C` 依赖 `∂M/∂q`，而 `M` 本身由数值雅可比构成），是计算量最大、也是数值误差主要来源的环节（见 §4.3）。
- **正动力学**：`q̈ = M⁻¹(τ - Cq̇ - G - Fq̇)`，求解前检查 M 的条件数，接近奇异时改用伪逆兜底。
- **逆动力学**：`τ = Mq̈ + Cq̇ + G + Fq̇`，用于计算力矩控制与 ILC 前馈。

### 3.4 控制策略

**计算力矩控制（CTC）**：利用动力学模型做前馈线性化，将非线性系统解耦为独立的二阶线性系统：

$$\tau = M(q)(\ddot{q}_d + K_p e + K_d \dot{e}) + C\dot{q} + G$$

实测追踪 RMSE 约 0.0008 rad，是本系统精度最高的控制器。

**迭代学习控制（ILC）**：针对重复执行同一轨迹的场景，通过历次跟踪误差逐轮改进前馈力矩。学习律为 PD 型：

$$u_{k+1}(t) = u_k(t) + K_p e_k(t{+}1) + K_d \dot{e}_k(t{+}1)$$

其设计包含三个关键点，详见 §4.2。

### 3.5 学习算法

**行为克隆（BC）**：以计算力矩控制器为专家采集 (状态, 力矩) 数据对，用监督学习拟合策略网络。关键在于对输入状态与输出力矩做标准化（各关节力矩量级相差可达数十倍），标准化后闭环跟踪 RMSE 约 0.013 rad。

**PPO**：Actor-Critic 架构的强化学习，以末端到目标的距离为奖励。

## 4. 关键设计决策与调试记录

> 本节记录开发过程中定位的若干非平凡问题及其解决方案。这些记录对维护者理解"为什么代码是现在这个样子"至关重要。

### 4.1 逆运动学的状态污染

**问题**：IK 求解器在迭代过程中反复调用 `set_joint_angles` 更新机械臂内部状态。早期实现中，求解失败时不恢复该状态，导致机械臂内部关节角停留在失败位形。这会污染后续操作：
- `get_end_effector_position()` 返回失败位形的位置；
- 下一次未提供 `initial_guess` 的 IK 会以被污染的角度为初始猜测，使原本可达的目标点也求解失败，形成连锁污染。

**现象**：同一份代码，FK 全零位姿两次运行给出不同的"零位坐标"——这本不可能，因为 FK 是纯函数。根因是零位坐标读取前，内部状态已被上一次失败的 IK 污染。

**解决**：求解前保存 `saved_angles`，仅在成功时保留新状态，失败时回滚。`_ik_jacobian` 与 `_ik_optimization` 统一此语义。

**教训**：带内部状态的迭代求解器必须保证失败路径不留副作用，否则会产生难以复现的连锁 bug。

### 4.2 迭代学习控制的收敛

ILC 的实现经历了多次迭代，最终稳定方案包含三个缺一不可的要素：

1. **学习律时序对齐**：力矩 `u(t)` 影响的是 `t` 之后的状态，因此必须用**下一时刻**误差 `e(t+1)` 修正 `u(t)`，而非同时刻 `e(t)`。早期用同时刻误差导致相位错配，误差不降反升直至发散。

2. **逆动力学前馈初始化**：第一轮控制量用 `inverse_dynamics(q_ref, q̇_ref, q̈_ref)` 计算，而非从零或仅重力补偿开始。这使第一轮误差就很小，后续是在良好起点上精修。

3. **前馈学习 + PD 反馈组合**：这是长轨迹收敛的关键。本动力学模型的逆/正动力学在小惯量关节（Joint 4）上存在轻微数值不一致（源于 §4.3 的两层数值微分），使纯开环前馈在 5 秒长轨迹上单调漂移，末端误差可达 1.1 rad。这种**随时间累积的系统性漂移不是 ILC 能学掉的**——ILC 只能修正可重复误差，纯开环 ILC 反而会在追逐漂移的过程中被高频化、发散。解决方案是采用 ILC 的标准工程用法：`总力矩 = ILC前馈 + PD反馈`，反馈压住漂移，ILC 在其上学习精细前馈。

**验证结果**：三要素齐备后，5 秒轨迹 20 轮迭代，误差稳定在 0.002 rad 量级，Joint 4 末端误差趋近 0。

**调试教训**：验证时曾用 2 秒、3 秒短轨迹得到"收敛"的假象，直到用完整 5 秒轨迹才复现发散——**测试轨迹长度必须覆盖实际使用场景**，短轨迹会掩盖累积性问题。

### 4.3 动力学计算的性能与精度权衡

科氏矩阵 `coriolis_matrix` 为两层数值微分嵌套：`C` 依赖 `∂M/∂q`（对质量矩阵数值微分），而 `M` 本身由数值雅可比构成。这带来两个后果：

- **性能**：每次 `forward_dynamics` 都要计算完整的 `C`，是仿真中最重的环节。长轨迹多轮迭代（如 ILC）耗时明显。
- **精度**：小惯量关节（Joint 4）受数值误差影响最大，是 §4.2 中漂移的根源。

Christoffel 符号的三重循环已用 Numba 加速。若需进一步优化，可考虑解析动力学（如递归牛顿-欧拉法）替代数值微分，但会增加实现复杂度。当前实现在精度可接受的前提下优先保证了代码可读性。

### 4.4 模块导入的健壮性

`RobotSystem` 需导入全部进阶控制模块。早期将四个模块的导入置于同一 `try/except` 块中，任何一个模块的依赖问题（如 PyTorch 未正确安装）会导致整个块失败，**静默地**禁用所有进阶控制器（MPC/ILC/BC/PPO），而系统仍能以基础控制运行——维护者极难察觉 ILC 等模块实际未加载。

**解决**：拆分为独立的 `try/except`，各模块导入互不影响，失败时明确提示是哪个模块及原因。实例化时打印已注册控制器列表作为自检。

## 5. 使用教程

### 5.1 运动学：FK 与 IK

```python
from robotic_arm_new import RoboticArm
import numpy as np

arm = RoboticArm(num_joints=6)

# 正运动学
arm.set_joint_angles([0.5, 0.5, -0.5, 0, 0.5, 0])
print("末端位置:", arm.get_end_effector_position())

# 逆运动学（建议提供 initial_guess）
success, angles = arm.inverse_kinematics([0.3, 0.1, 0.4],
                                         initial_guess=np.zeros(6))
```

### 5.2 轨迹规划与追踪

```python
from robotic_system import RobotSystem

system = RobotSystem(mode='dynamics')

# 规划五次多项式轨迹（速度/加速度两端为零，最平滑）
traj = system.plan_trajectory([0]*6, [0.5, 0.5, -0.5, 0, 0.5, 0],
                              method='quintic', duration=2.0, num_points=100)

# 计算力矩控制追踪（精度最高）
results = system.execute_trajectory(traj, controller_name='computed_torque')
```

三种插值方法的取舍：`linear`（速度恒定、起停有冲击）、`cubic`（速度连续、端点加速度非零）、`quintic`（速度加速度两端均为零、最平滑，推荐用于动力学追踪）。

### 5.3 ILC 迭代学习

```python
system = RobotSystem(mode='dynamics')
traj = system.plan_trajectory([0]*6, [0.5]*6, method='quintic',
                              duration=5.0, num_points=500)

# 前馈学习 + PD 反馈，误差逐轮下降
system.train_ilc_trajectory(traj, iterations=20)
```

### 5.4 GUI 控制

```bash
python src/gui_control.py
```

滑块控制各关节角度，输入目标位置可实时求解 IK 并更新 3D 显示。

## 6. 故障排除

| 现象 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: No module named 'src'` | 测试脚本用 `from src.xxx import`，但从 tests 目录直接运行 | 从项目根目录运行：`python -m tests.test_xxx`，或 `PYTHONPATH=. python tests/test_xxx.py` |
| `ModuleNotFoundError: No module named '_tkinter'` | Python 未编译 Tk 支持（常见于 macOS Homebrew Python） | `brew install python-tk@3.12`（版本号对应你的 Python） |
| 3D 绘图报 `SystemError: null argument to internal routine` | macOS 默认 matplotlib 后端渲染 3D 时的已知问题 | 文件顶部 `import matplotlib; matplotlib.use('TkAgg')`，须在 `import pyplot` 之前 |
| IK 返回 `success=False` | 目标点在工作空间外或奇异区附近 | 属预期行为；提供合理 `initial_guess`，或改用可达目标点 |
| ILC 误差先降后升直至发散 | 纯开环 ILC 在长轨迹上追逐模型漂移 | 使用 `train_ilc_trajectory`（已内置 PD 反馈）；勿用纯开环 ILC 跑长轨迹 |
| 实例化 `RobotSystem` 后进阶控制器缺失 | 对应模块导入失败（常为 PyTorch 未安装） | 查看实例化时的提示信息，按提示安装缺失依赖；"已注册控制器"打印可确认哪些已加载 |
| 动力学仿真/ILC 运行缓慢 | 科氏矩阵为两层数值微分，计算量大 | 属已知性能特征；调试时可用较短轨迹或较大 `dt` 验证趋势 |
